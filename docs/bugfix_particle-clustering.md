# SCHISM 파티클 해안선 클러스터링 버그 수정

**생성일**: 2026-02-24
**상태**: 계획 수립 중
**관련 파일**: `lib.rs` (파티클 생성/리스폰 로직), `mesh.rs` (삼각형 탐색/보간)

---

## 문제 요약

SCHISM 해류 파티클이 해안선 경계에 과도하게 밀집되며, 외해 수역은 텅 비는 현상이 발생한다. Windy 스타일 리팩토링(화면 공간 밀도 관리, 셀 기반 리스폰) 적용 후 나타난 문제이다.

### 증상

- 파티클이 좌우 해안선을 따라 밀집된 색상 덩어리(무지개색/마젠타)를 형성
- 내만(灣) 중앙 수역은 파티클이 거의 없음
- 외해 일부에 극히 드문 산발적 파티클만 존재
- 줌인 시 해안선 경계에 파티클이 한 줄로 쌓여 있는 패턴 확인

---

## 원인 분석

### 원인 1: `generate_particle_mesh` 결정적 폴백 (심각도: 높음)

**위치**: `lib.rs` 2093~2137행

```
generate_particle_mesh()
  → mesh_bounds 내 랜덤 좌표 10회 시도
  → 전부 실패 시 → mesh_bounds 중심 좌표 반환 (결정적)
```

mesh_bounds 영역 내 삼각형 커버리지가 낮을 때(바다+육지 혼합 영역), 10회 랜덤 시도 중 삼각형 히트 확률이 낮다. 실패 시 **모든 파티클이 동일한 mesh_bounds 중심 좌표**에 생성된다.

**발생 흐름**:
1. 초기 벌크 생성(1020~1029행): target 수만큼 파티클 생성
2. `find_sparsest_valid_cell` → `spawn_in_cell` 시도 실패 시 `generate_particle_mesh` 폴백
3. 수천 개 파티클이 mesh_bounds 중심에 집중 생성
4. 다음 프레임: 이 파티클들의 `mesh_interpolate_uv` 결과에 따라 리스폰 또는 이동
5. 리스폰 시 `find_sparsest_valid_cell` → 다시 해안선 셀로 이동

### 원인 2: `find_sparsest_valid_cell` 결정론적 순회 (심각도: 중간)

**위치**: `lib.rs` 2207~2224행

```rust
for row in 0..rows {
    for col in 0..cols {
        // 동일 최소값일 때 항상 좌상단(첫 번째) 셀 선택
    }
}
```

카운트가 동일한 셀이 다수일 때 **항상 행·열 순서상 가장 앞의 셀**이 선택된다. 초기 상태에서 모든 유효 셀의 카운트가 0이면, 반복적으로 같은 셀이 선택되어 해당 셀에 파티클이 과도하게 할당된다.

### 원인 3: 셀 마스크 커버리지 불일치 (심각도: 중간)

**위치**: `lib.rs` 2175~2204행

`build_mesh_cell_mask`는 셀당 5개 샘플 포인트(중심 + 4모서리)만 검사한다. 셀의 5%만 삼각형이 덮고 있어도 유효로 판정될 수 있다.

```
셀 마스크: "이 셀에 메시 있음" ✓ (5개 중 1개 히트)
실제 스폰: 3회 랜덤 시도 → 3회 모두 육지에 착지 → 실패
```

해안선 셀은 마스크=유효이지만 실제 스폰 성공률이 극히 낮아, 반복적으로 선택되면서도 스폰이 실패하는 악순환이 발생한다.

### 원인 4: `try_spawn_in_cell` 시도 횟수 부족 (심각도: 낮음)

**위치**: `lib.rs` 2267~2301행

셀당 랜덤 시도 3회는 메시 커버리지가 낮은 해안선 셀에서 충분하지 않다.

| 셀 내 메시 커버리지 | 3회 시도 성공률 | 10회 시도 성공률 |
|:---:|:---:|:---:|
| 50% | 87.5% | 99.9% |
| 20% | 48.8% | 89.3% |
| 5% | 14.3% | 40.1% |

## 수정 계획

### Fix 1: `generate_particle_mesh` 폴백 랜덤화

**현재**: 10회 실패 → `mesh_bounds` 중심 (결정적)

**수정**: 10회 실패 → 추가 20회 랜덤 시도 → 전부 실패 시 **랜덤 좌표** 반환 (결정적 중심점 제거)

```
수정 후 generate_particle_mesh():
  1차: mesh_bounds 내 랜덤 좌표 10회 시도 (기존)
  2차: 삼각형 무작위 선택 → 해당 삼각형 내부 랜덤 좌표 생성
       → 확정적으로 유효한 위치에 스폰
```

핵심: R-tree에서 삼각형을 직접 선택하여 그 내부에 스폰하면 실패가 원천적으로 불가능하다.

**구현 방향**:
- `tri_rtree`에서 랜덤 인덱스로 삼각형 하나를 선택
- 삼각형 3개 꼭짓점의 가중 평균으로 내부 좌표 생성
- 이 방식은 삼각형이 존재하는 한 100% 성공

### Fix 2: `find_sparsest_valid_cell` 랜덤 타이브레이킹

**현재**: 최소 카운트 셀 중 첫 번째 셀 반환 (행·열 스캔 순서)

**수정**: 최소 카운트 셀 후보를 모두 수집 → 그 중 랜덤으로 선택

```
수정 후:
  1. 전체 유효 셀 순회 → 최소 카운트 값 확인
  2. 최소 카운트와 같은 셀들을 후보 리스트에 수집
  3. 후보 리스트에서 랜덤 선택
```

메모리 오버헤드를 피하려면 **Reservoir Sampling** 적용: 후보 리스트 없이 1-패스로 랜덤 선택 가능.

```
count = 0
for each valid cell with min_count:
    count += 1
    if random(0..count) == 0:
        selected = this cell
```

### Fix 3: 셀 마스크 커버리지 비율 추가

**현재**: boolean 마스크 (유효/무효)

**수정**: float 커버리지 비율 마스크 + 가중 셀 선택

```
build_mesh_cell_mask() 수정:
  - 샘플 포인트를 5개 → 9개 (3×3 그리드)로 증가
  - 반환: Vec<f32> (0.0 ~ 1.0, 히트 비율)
  - 마스크 임계값: 커버리지 > 0.0이면 유효

find_sparsest_valid_cell() 수정:
  - 커버리지 비율을 가중치로 사용
  - 동일 카운트 셀 중 커버리지가 높은 셀 우선 선택
```

**효과**: 메시가 50% 이상 덮는 해양 셀이 5%만 덮는 해안선 셀보다 우선 선택된다.

### Fix 4: 삼각형 직접 선택 리스폰 경로 추가

`spawn_in_cell`이 실패할 때, 메시 전체에서 랜덤 삼각형을 선택하여 스폰하는 경로를 추가한다.

```
spawn_in_cell 실패 시:
  현재: 8-인접 셀 시도 → None 반환
  
  수정: 8-인접 셀 시도 → 실패 시 → spawn_in_random_triangle()
    → R-tree에서 뷰포트 내 삼각형 후보 탐색
    → 랜덤 선택 → 삼각형 내부 좌표 생성
    → 100% 성공
```

**삼각형 내부 랜덤 좌표 생성 공식**:

```
r1 = sqrt(random()), r2 = random()
P = (1 - r1) * A + r1 * (1 - r2) * B + r1 * r2 * C
```

이 공식은 삼각형 내부에 균등 분포를 보장한다.

### Fix 5: `try_spawn_in_cell` 시도 횟수 적응적 조정 (선택사항)

**현재**: 고정 3회

**수정**: 셀 커버리지 비율에 따라 시도 횟수 조정

```
coverage = mesh_coverage[cell_idx]
max_tries = if coverage > 0.5 { 3 } 
            else if coverage > 0.2 { 6 }
            else { 10 }
```

## 구현 우선순위

| 순서 | Fix | 효과 | 난이도 | 비고 |
|:---:|:---:|:---:|:---:|:---|
| **1** | Fix 4 (삼각형 직접 선택) | 핵심 — 스폰 실패 원천 제거 | 중 | R-tree 접근 필요 |
| **2** | Fix 1 (폴백 랜덤화) | 중심 클러스터링 완전 제거 | 낮 | Fix 4와 연계 |
| **3** | Fix 2 (랜덤 타이브레이킹) | 초기 분배 균일화 | 낮 | Reservoir sampling |

| **5** | Fix 5 (적응적 시도) | 미세 개선 | 낮 | Fix 3 의존 |

**최소 필수 수정**: Fix 1 + Fix 2 + Fix 4를 적용하면 클러스터링 문제를 해결할 수 있다.

## 검증 방법

1. **초기 생성 분포 확인**: `generate_particle_mesh` 폴백 호출 횟수 로그 → 0에 가까워야 함
2. **셀 카운트 분산**: 유효 셀들 간 파티클 카운트의 표준편차 확인 → 낮을수록 균일
3. **시각적 확인**: 해안선 클러스터링 해소, 외해 수역에 파티클 분포 확인
4. **프레임 #0 진단 로그**: `none_count` (보간 실패) 비율이 5% 이하여야 함
